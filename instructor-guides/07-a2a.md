# Lab (Module 7) — A2A Protocol on AgentCore

**AWS doc**: [Deploy A2A servers in AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html)

A2A = Agent-to-Agent protocol. Standard way for agents to discover each other (via **Agent Cards**) and talk (**JSON-RPC** over HTTP). AgentCore hosts A2A servers on port 9000 mounted at `/`.

## Scaffold

The AWS doc says `agentcore create --protocol A2A` prompts interactively. **Current CLI requires more flags.** Use this:

```bash
mkdir ~/a2a-experiment && cd ~/a2a-experiment
agentcore create \
  --name my_a2a_server \
  --framework Strands \
  --model-provider Bedrock \
  --protocol A2A \
  --defaults
cd my_a2a_server
```

## Run it locally

```bash
agentcore dev
```

Opens the AgentCore inspector in a browser. Agent listens on port **9000**.

## Point at in the code (`app/MyAgent/main.py`)

Three things — very different from the HTTP entrypoint pattern:

1. **`serve_a2a(StrandsA2AExecutor(agent))`** — replaces `BedrockAgentCoreApp` / `@app.entrypoint`. Handles port 9000, agent card, health checks, header propagation.
2. **`StrandsA2AExecutor(agent)`** — adapter that makes a plain Strands agent speak A2A
3. **Same Strands `Agent(model=..., tools=[...])` you saw in M2** — the agent itself is unchanged; only the *serving layer* is different

Say: "Same Strands agent, different serving protocol. A2A is a wire format, not a framework."

## Test with curl

Invoke via JSON-RPC:
```bash
curl -X POST http://localhost:9000/ \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": "req-001",
    "method": "message/send",
    "params": {
      "message": {
        "role": "user",
        "parts": [{"kind": "text", "text": "what is 101 * 11?"}],
        "messageId": "12345678-1234-1234-1234-123456789012"
      }
    }
  }' | jq .
```

Fetch the agent card:
```bash
curl http://localhost:9000/.well-known/agent-card.json | jq .
```

Show attendees the agent card — this is how other agents discover *what your agent does* without human docs.

## What A2A is really for

The scaffolded server is **one side of the conversation**. A2A shines when another agent (potentially in a different framework — LangGraph, Google ADK, etc.) discovers this one via its agent card and calls it. Full multi-agent A2A demos need a client agent — see AWS doc Step 5 or build a supervisor/worker pair.

For a first look: showing the server + agent card + JSON-RPC round-trip is enough to explain the concept.

## Deploy (optional)

```bash
agentcore deploy
```

Deploys as A2A on AgentCore Runtime. Auth is SigV4 or Cognito OAuth (see M3 pattern). Remote invocation is more involved — requires the `a2a` Python client library and bearer tokens. See AWS doc Steps 4–5.

## Cleanup

Nothing if you only ran `agentcore dev`. If deployed:
```bash
agentcore remove all
agentcore deploy
```
